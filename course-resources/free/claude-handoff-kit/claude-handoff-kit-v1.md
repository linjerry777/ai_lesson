# Claude 交接檔套件 v1

> JERRY.AI｜小訊教你用 AI
> 對話聊太久，Claude 開始忘記前面講過的事？先叫它寫交接檔，開新對話再讀回來，就能接著做。

這份檔案分成四段：

1. 什麼時候該換對話
2. 指令一：在舊對話裡寫交接檔
3. 指令二：在新對話裡讀交接檔
4. HANDOFF.md 空白模板（可以自己填，或對照 Claude 寫得對不對）

用網頁版或 App、沒有用 Claude Code 的人，看最後的「沒有 Claude Code 的版本」。

---

## 1. 什麼時候該換對話

出現下面任一種情況，就該換：

- 它開始問你**已經講過**的事
- **同一個錯**重複出現
- 畫面出現**壓縮**（compact）提示

如果是換做一件**不相關**的工作，直接開新對話就好，不用交接。

> 為什麼會忘：Claude Code 的對話快滿時會自動壓縮，比較舊的內容會被濃縮成摘要。摘要比原文短，你講過的規則、檔名、放棄過的做法，就可能不在裡面了。

---

## 2. 指令一：在舊對話裡寫交接檔

在**快滿的那個對話**裡，整段貼上：

```
這個對話快滿了，我要換到新對話繼續。請把目前的工作寫成一份交接檔，存成 HANDOFF.md。

照下面五段寫，每段用條列：
1. 目標：這件事最後要做出什麼，做到什麼算完成。
2. 已做的決定：定案的做法和原因。試過但放棄的做法也要寫，註明為什麼放棄。
3. 目前進度：哪些做完了；哪些做到一半，做到哪裡。
4. 下一步：接下來要做的事，照順序列。第一項要寫到可以直接動手。
5. 相關檔案：路徑加一句說明。我講過的規則和偏好也列在這一段。

規則：只寫這次對話裡真的發生過的事。不確定的標「待確認」，不要補猜的內容。寫完把全文貼給我看。
```

**成功長這樣：**

- 專案資料夾裡多了一個 `HANDOFF.md`
- 五段都有內容，「已做的決定」裡有寫到放棄過的做法
- 你看一遍，沒有它自己編出來的東西。有的話叫它刪掉，再存一次。

---

## 3. 指令二：在新對話裡讀交接檔

先開一個新對話（在 Claude Code 裡輸入 `/clear`），再貼上：

```
先讀 HANDOFF.md。讀完用三句話告訴我：你理解的目標、目前進度、下一步。等我確認之後，從「下一步」的第一項開始做。
```

**成功長這樣：**

- 它說出來的三句話跟你心裡想的一樣
- 不一樣的地方，你直接糾正它，再叫它把正確的寫回 HANDOFF.md

---

## 4. HANDOFF.md 空白模板

想自己寫，或要對照 Claude 寫的有沒有漏，就用這個模板：

```markdown
# HANDOFF

## 1. 目標
- 最後要做出：
- 做到什麼算完成：

## 2. 已做的決定
- 定案：（做法）—— 原因：
- 放棄：（做法）—— 為什麼放棄：

## 3. 目前進度
- 已完成：
- 做到一半：（做到哪裡）

## 4. 下一步
1. （第一項寫到可以直接動手）
2.
3.

## 5. 相關檔案
- `路徑`：一句說明
- 規則與偏好：
```

## 沒有 Claude Code 的版本（網頁版或 App）

在舊對話貼：

```
這個對話快滿了，我要換到新對話繼續。請把目前的工作整理成一份交接筆記，直接貼在回覆裡，分五段：目標、已做的決定（含放棄的做法和原因）、目前進度、下一步、相關檔案或資料。只寫這次對話裡真的發生過的事，不確定的標「待確認」。
```

把它回覆的整段複製起來，貼到新對話的第一則訊息，前面加一句：

```
這是上一個對話的交接筆記，先讀完，告訴我你理解的下一步。
```

---

## 不想換對話的時候

Claude Code 也可以手動壓縮，而且能指定要保留什麼：

```
/compact 保留已做的決定和檔案路徑
```

想看目前對話裝了多少東西，輸入 `/context`。

交接檔的好處是：內容你看得到、也改得了，隔天繼續做或換別的工具都用得上。
